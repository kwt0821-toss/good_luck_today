# 방꾸미기 배치·보유 규칙 v2 (탭 → 미리보기 → 확정)
2026-10-14 · room-spec 추가 · tutorial-1.7 step 4 반영

## 1. 핵심 흐름
1. 편집 모드에서 서랍 아이템을 탭하면, 자동으로 고른 빈 칸에 **미리보기(pending)** 상태로 바로 나타나요. 서버 저장은 아직 하지 않아요.
2. 미리보기 위에 떠 있는 툴바: **✕ 취소 · ⟳ 회전 · ✓ 확정**. 서랍을 열어 둔 채로 방 위쪽에 띄워요.
3. ✓를 누르면 클라이언트 검증 → `POST /rooms/{roomId}/placements` → 서버가 다시 검증 → 확정되고 sfx item-place + 바운스. 실패하면 미리보기를 빨간색으로 바꾸고 이유를 토스트로 알려요.
4. ✕(또는 다른 서랍 아이템 탭, 빈 곳 탭 아님)를 누르면 미리보기가 사라지고 아무것도 바뀌지 않아요. 미리보기는 동시에 1개만 있어요.

## 2. 미리보기 이동 방법 (권장: 2가지 모두, 기본은 ①)
| 방법 | 동작 | 평가 |
|---|---|---|
| ① **미리보기를 드래그** | 아이템을 잡고 끌면 칸 단위로 스냅. 손가락에 가려지지 않게 고스트를 손가락보다 24pt 위에 그림 | 가장 직관적 (포켓캠프·Habbo·그리드 배치 일반 패턴). 기본 |
| ② **목표 칸 탭** | 편집 중에 빈 바닥 칸을 탭하면 미리보기가 그 칸으로 순간이동 | 작은 화면과 정밀 이동에 좋고, 드래그가 어려운 사용자를 위한 대안 (드래그 패턴 가이드 권장) |
| ③ 화살표 미세조정 | ↖↗↙↘ 4방향 | 아이소메트릭에서는 방향이 헷갈려요. **넣지 않음** (필요하면 접근성 설정에서) |
- 이동 중에는 바닥 격자를 보여 주고, 놓을 수 있는 칸은 초록, 겹치거나 범위를 벗어난 칸은 빨강으로 표시해요. 빨강 상태에서는 ✓를 비활성으로 두고 이유 칩을 보여 줘요 ("다른 가구와 겹쳐요" / "여기는 놓을 수 없어요").
- 회전: ⟳ 한 번에 기본 ↔ 좌우 반전(아이소메트릭 2방향). 회전 후 칸이 겹치면 빨강.
- 이미 놓인 아이템을 탭하면 같은 미리보기 상태로 들어가고, 툴바에 **⤓ 서랍에 넣기**가 추가돼요. 이때 ✕는 원래 자리로 되돌려요.

## 3. 자동 위치 선택 (suggest)
- 가구·소품: 카메라 중앙에 가까운 순서로 첫 번째 유효 칸(크기와 회전 포함). 방 안의 칸을 순서대로 확인하고, 기본 방향으로 안 되면 반전 방향도 확인해요.
- 벽 꾸미기: 왼쪽·오른쪽 벽 슬롯 중 비어 있고 높이가 맞는 첫 슬롯.
- **빈 칸이 하나도 없으면**: 중앙에 빨간 미리보기를 띄우고 "방에 자리가 없어요 · 다른 아이템을 서랍에 넣어 보세요"를 보여 주며 ✓는 비활성이에요.
- 튜토리얼에서는 suggestTile을 우선 써요 (newuser c5,r2).

## 4. 벽지·바닥 (타일 칠하기)
- 탭하면 **현재 타입과 다른 타일**을 자동으로 골라 그 타일 하나만 미리보기로 칠해요 (바닥은 중앙에 가까운 순서, 벽은 L→R).
- 미리보기 툴바: ✕ · ✓ · **전체 바꾸기**(방 전체 바닥 또는 벽 전체를 미리보기로) · 이동(①/② 같은 방식, 칸 단위).
- **모든 타일이 이미 같은 타입이면**: 아무 칸에나 빨간 미리보기를 띄우고 "이미 같은 벽지가 깔려 있어요"(바닥은 "이미 같은 바닥이 깔려 있어요")를 보여 주며 ✓와 전체 바꾸기는 비활성.
- 칠하기는 개수를 쓰지 않아요. 한 번 갖고 있으면 모든 방, 모든 칸에서 계속 쓸 수 있어요.

## 5. 보유·중복 규칙
| 종류 | 보유 방식 | 배치 |
|---|---|---|
| 가구·소품·벽 꾸미기 (상점) | **개수(count)** 보유. 여러 개 살 수 있어요 (아이템당 상한 `maxOwn` 기본 5, 큰 가구 3) | 1개 = 모든 방을 통틀어 1자리. `placed(전체) ≤ count` |
| 출석·이벤트 한정 | count 최대 1, 다시 살 수 없음 | 같음 |
| 벽지·바닥 | 보유 여부(무제한) | 칠하기 |
- 서랍 타일에는 "남은 개수 / 전체"를 보여 줘요 (예: 1/2). 남은 게 0이면:
  - 다른 방에 있으면 "다른 방에 있어요 · {방이름}"과 [이 방으로 옮기기] (원래 방에서 빼서 미리보기로 → ✓를 누르면 원래 방에서 제거하고 여기에 배치하는 것을 한 트랜잭션으로 처리)
  - 상점 아이템이면 [하나 더 사기] (maxOwn 미만일 때). 한정 아이템이면 "한정 아이템이에요"
- 판매·환불은 하지 않아요 (경제 단순화). 서랍에 넣으면 count가 돌아와요.

## 6. 편의 기능
- **되돌리기 1단계**: 마지막 확정·서랍에 넣기·전체 바꾸기를 1번 되돌림 (편집 세션 안에서만).
- **모두 서랍에 넣기**: 편집 메뉴 › "가구 모두 넣기" (확인 시트). 벽지·바닥은 그대로.
- 레이아웃 저장(프리셋)은 v2에 넣지 않아요 (후보).
- 편집을 마칠 때 확정되지 않은 미리보기는 자동으로 취소돼요.

## 7. 상태
`idle(편집)` → 서랍 탭 → `preview(valid|invalid)` → ✓ → `committing` → 성공 `placed` / 실패 `preview(invalid, reason)` · ✕ → `idle`

## 8. 데이터 모델
```json
inventory: [{ "itemId":"cushions", "count":2, "source":"shop|attendance|starter" }]
paints:    ["floor_wood_a","wall_night"]            // 보유한 벽지·바닥
rooms[roomId].placements: [{ "pid":"p_93f", "itemId":"cushions", "c":5, "r":2, "flip":false }]   // 벽 아이템은 {wall:"L", t, heightUnits}
rooms[roomId].floor[8][8], wallL[8], wallR[8]       // 타일 타입
```
- 불변식(서버): itemId별로 모든 방의 placements 개수 ≤ inventory.count. 겹침, 범위, 벽 슬롯 높이 검증.
- API: `POST /rooms/{id}/placements {itemId,c,r,flip,requestId}` · `PATCH .../{pid}` (이동·회전) · `DELETE .../{pid}` (서랍에 넣기) · `POST /rooms/{id}/placements/{pid}/move-from {fromRoomId}` · `POST /rooms/{id}/paint {kind:floor|wall, tiles:[...]|'all', type}` · `POST /shop/buy {itemId,qty}` (maxOwn 검사)
- 모든 쓰기는 requestId로 멱등 처리해요.

## 9. 예외 상황
- 확정 직전에 다른 기기에서 바뀐 경우 → 서버에서 409 → 최신 방을 다시 불러오고 "방이 바뀌어서 다시 불러왔어요"
- 방 해금 전에는 그 방의 placements를 보여 주지 않음 / 옮기기 대상에서도 제외
- 크기가 큰 가구가 회전해서 범위를 벗어나면 빨강
- 고양이(장식 고양이)가 있는 칸 → 고양이가 옆 칸으로 비켜요 (막지 않음)
