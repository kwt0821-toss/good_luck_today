# 뽑기 결과 화면 (draw reveal) — spec 1.0

Concept B 나이트 스타일이에요(메인 화면과 같은 토큰). 디자인 프레임은 390×844 pt, 콘텐츠 영역은 토스 내비 아래 741 pt예요. 목표는 **광고가 닫힌 뒤 1.2초 안에 카드가 읽히는 것**이에요. 실제로는 약 0.8초면 앞면이 보여요.

## 파일
- `draw-reveal.html`: 하나로 된 프로토타입이에요(카드 이미지·Poppins 포함, 약 1 MB).
  - 데모 버튼: 5★ / 레전드 / 스페셜 / 캐릭터 / 3★ 중복 / 1★ 중복 / 0.25배속.
  - URL 파라미터: `?c=tiger&t=900`은 정지 프레임, `&chrome=1`은 토스 바 표시, `&wait=800`은 서버 지연을 흉내 내요.
- `mockup-1-facedown.png`, `mockup-2-midflip.png`, `mockup-3-revealed-5star-new.png`: 1170×2532, t = 100 / 490 / 1500 ms.

- **아무 곳이나 톡**: 바로 최종 상태로 가요(t = 1500). 버튼 영역은 제외해요.
- **최종 상태에서 카드 톡**: 앞/뒤 뒤집기(0.45 s, cubic-bezier(.3,.7,.2,1.1)). 뒷면은 카드 `*_back.webp`예요.
- **reduced motion**: 흔들림·레이·파티클을 끄고 크로스페이드 250 ms로 바꿔요.

## 미리 받아 두기 (속도의 핵심)
1. 뽑기 버튼을 누르면 **광고 시작과 동시에** `POST /draw`를 보내요(서버가 결과 결정 + 보상 예약). 응답에는 cardId, isNew, dupPaw, 이미지 URL, 남은 횟수가 있어요.
2. 응답을 받으면 바로 앞면·뒷면 이미지를 `new Image()` + `decode()`로 미리 디코딩해요. 결과 화면 DOM(뒷면 카드 + 글로우)은 광고 중에 숨겨 둔 채로 마운트해요.
3. 보상 확정(포인트·토스 1원·도감 등록)은 **광고 완료 콜백**을 서버가 확인한 뒤에만 해요. 광고를 끝까지 안 보면 예약을 취소하고 뽑기 횟수도 돌려줘요.
4. 광고가 닫혔을 때 준비가 안 됐다면 뒷면 카드 펄스(0–150 ms 구간 반복)를 유지해요. 준비되면 그 시점에서 t = 150부터 이어가요.
5. **최대 1.5 s**까지 기다려요. 그래도 안 되면 대체 처리해요.
   - 결과는 있는데 이미지가 없으면 썸네일(`thumbs/*_thumb.webp`)로 뒤집어요.
   - 결과가 없으면 "카드를 가져오는 중이에요…" 문구 + 재시도 버튼을 보여요. 뽑기는 서버 기준으로 이미 확정이니 재시도는 같은 결과를 다시 받아요(멱등 drawId).
6. 다음 뽑기용으로 뒷면 카드(`card-facedown`)와 등급 연출 자원은 앱 시작 때 캐시해요.
